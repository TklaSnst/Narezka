# Архитектура

Статус: проектная. Пункты с пометкой **(проверить на этапе 0)** — гипотезы, их подтверждает или меняет этап 0.

## 1. Стек

| Компонент | Выбор | Зачем |
|---|---|---|
| Язык | Rust (Cargo workspace) | Безопасность, хорошие биндинги, `cargo-deb` |
| GUI | egui / eframe, бэкенд **glow** (OpenGL) | Wayland из коробки, холст с drag-and-drop, свои шейдеры через `PaintCallback`, совместимость с mpv render API |
| Превью-плеер | libmpv (render API → OpenGL FBO/текстура), подтверждено на 0.5 | VAAPI-декод, точный seek, A/V-синхронизация, проигрывание отрезка |
| Рендер | системный `ffmpeg` (subprocess), граф `filter_complex` генерируется из модели | Надёжно, все кодеки, `-progress` для прогресса |
| Распознавание речи | whisper.cpp через свои FFI-биндинги (bindgen, `-sys` крейт), бэкенд Vulkan, модель large-v3-turbo + Silero VAD (подтверждено на 0.2) | Таймкоды слов, русский, работает на AMD без ROCm |
| LLM | llama.cpp (бэкенд Vulkan) — `llama-server` отдельным процессом, модель Qwen3.5-9B Q4_K_XL (предварительно, 0.3) | Смысловая нарезка, заголовки, ключевые слова |
| Эмбеддинги | Qwen3-Embedding-0.6B Q8_0 через тот же `llama-server` (`--embedding`) | Страховочный алгоритм смены темы |
| Растеризация текста/графики | cosmic-text + tiny-skia | Один растеризатор для превью и рендера → совпадение текста |
| Субтитры | растры `sc-raster` по состояниям фразы (превью и рендер), см. DECISIONS 2026-11-15 | Совпадение превью и рендера, плашка текущего слова, цвета ключевых слов |
| i18n | Fluent (`fluent-bundle`) | RU/EN |
| Пути | `directories` (XDG) | Переносимость |
| Уведомления | D-Bus (`notify-rust`) | mako/dunst/swaync на Hyprland |
| Конфиги | serde + TOML (настройки, шаблоны), JSON (кэш анализа) | Читаемо руками |
| Упаковка | `cargo-deb` | |

whisper.cpp — сабмодуль `third_party/whisper.cpp` (закреплённая версия), крейт `sc-whisper-sys` собирает его статически
через cmake (Vulkan) и генерирует биндинги bindgen (`whisper-rs` отстаёт: нет таймкодов токенов на исходной шкале при VAD). llama.cpp — сабмодуль `third_party/llama.cpp` (b11384); крейт `sc-llama` собирает из него `llama-server` (статически,
Vulkan) и запускает его отдельным процессом на свободном порту localhost: в одном процессе две копии ggml
(whisper и llama) конфликтуют, а завершение процесса гарантированно освобождает VRAM. Бинарник: `SC_LLAMA_SERVER` →
`llama-server` рядом с исполняемым файлом → собранный `build.rs`.
До инициализации ggml выставлять `GGML_VK_DISABLE_HOST_VISIBLE_VIDMEM=1` (без ReBAR ×5 к скорости whisper, см. `phases/00-spikes.md` 0.2).

## 2. Модули (crates)

```
crates/
  core       — модель данных (шаблоны, пачка, шортсы, ассеты), сериализация, валидация
  media      — ffprobe, извлечение аудио/кадров, проверка возможностей ffmpeg (encoders, hwaccels)
  analysis   — whisper, разметка предложений/пауз, LLM-нарезка, эмбеддинги, кэш, загрузка моделей
  whisper-sys — FFI к whisper.cpp (сборка из third_party)
  llama      — llama-server из third_party/llama.cpp: сборка, запуск процесса, HTTP (эмбеддинги, затем чат с JSON-схемой)
  raster     — отрисовка текстовых слоёв, капсул, обложек в RGBA (cosmic-text + tiny-skia)
  mpv        — свои FFI-объявления к libmpv (render API, только асинхронные вызовы)
  compositor — GPU-композиция превью: фон (blur-шейдер), кропы видео, слои, safe zones
  render     — построение команд ffmpeg, последовательность растров субтитров, очередь задач, прогресс
  library    — библиотека ассетов, история «как в прошлый раз», пресеты
  i18n       — ресурсы Fluent
  app        — egui-приложение (бинарник shortscutter)
```

Пакеты называются `sc-<имя>` (`sc-core`, `sc-i18n`…), бинарник — пакет `shortscutter` в `crates/app`.

Правило зависимостей: `core` ни от чего не зависит (в нём и общие формулы кропа для превью и рендера); `app` зависит от всех; `render` и `compositor`
не зависят друг от друга, но оба читают одну и ту же модель из `core` (источник истины — модель, а не превью).

## 3. Модель данных (описание, не код)

**Template**
- `canvas`: ширина, высота (по умолчанию 1080×1920)
- `background`: один из — `Blur { source: main, darken %, scale }`, `Color`, `Gradient`, `Image(asset)`, `Video(asset, loop)`
- `layers` (упорядоченный список, z-order):
  - `MainVideo { crop_rect (в долях исходника), dest_rect (в долях холста), corner_radius, border, shadow }` — может быть несколько (шаблон «Два экрана»)
  - `Text { content с разметкой акцента *…*, font, size, color, accent_color, accent_mode: Color|Plate, outline, shadow, rect, align }`
    — поддерживает подстановки `{part}` (номер среди принятых шортсов ролика), `{title}`; не влезающий текст уменьшается
  - `Image { asset, rect, opacity }`
  - `Capsule { logo asset, text, colors, rect }`
  - `Subtitles { style, rect, mode: Static|WordHighlight|Reveal, words_per_line, colors }`
  - `Shape { rect, paint: Solid|Linear, corner_radius }` — плашка, градиент-затемнение
  - `BannerSlot { rect }` — место под баннер пачки
- `MainVideo.border` (внутрь слоя) и `shadow { color, blur, dx, dy }`; у фонов `Image`/`Video` — `darken`
- все координаты — в долях холста (0..1), длины (радиусы, толщины, кегль) — в долях ширины холста,
  чтобы шаблон работал при любом выходном разрешении

**Batch** (пачка)
- `sources[]` (путь, ffprobe-информация, хэш, статус анализа)
- `template` (ссылка + локальные правки)
- `banner: Option<{asset, rect, text_layer?}>`
- `insert_default: Option<asset>`
- `output: { dir, base_name, container, codec, quality preset/advanced, resolution, fps, conflict_policy, export_metadata, notify }`

**Short** (шортс)
- `source_id`, `in`, `out` (секунды, привязаны к границам слов)
- `title`, `score`, `reason`, `status: Candidate|Accepted|Rejected`
- `insert: Option<{asset, at (сек. внутри шортса), hide_banner}>`, флаги `no_banner`, `no_insert`
- `cover: Option<{source: Frame(t)|Image(asset), overlays[], duration_frames}>`
- `subtitle_overrides` (исправленный текст)

**Transcript** (кэш по хэшу файла): слова `{text, start, end, prob}`, предложения, паузы, исключённые зоны.

**Asset** (библиотека): тип (banner/insert/image/font/background), путь (копия в библиотеке), метаданные
(размер, длительность, ориентация, альфа), теги, история использования (дата, позиция, параметры).

## 4. Пайплайн анализа

1. `ffmpeg` → моно 16 кГц `s16le` в память через пайп (не `f32le`: при выводе во float ffmpeg сводит стерео без нормировки).
2. Whisper (Vulkan) со встроенным Silero VAD → слова с таймкодами (`whisper_full_get_token_t0/t1` — уже на исходной
   шкале) и границы речи (VAD-сегменты). Без VAD — галлюцинации на паузах и фоне. DTW-таймкоды — по решению 0.2
   (требуют выключить flash attention). Словарь терминов из настроек передаётся как initial prompt.
   Модель выгружается из VRAM после работы (Whisper и LLM не держим одновременно — 8 ГБ).
   Транскрипт (слова с таймкодами токенов и DTW, сегменты, участки речи VAD) кэшируется в `analysis/<hash>.transcript.json`;
   ролики пачки распознаются по одному, сразу после импорта.
3. Разбиение на предложения (`analysis::sentences`): конец — `.!?…` или пауза между словами ≥1.2 с; длиннее 30 с —
   делится по самой длинной паузе или запятой; одинаковые подряд помечаются `repeat` (петли whisper).
   Паузы — промежутки между словами, внутри них VAD даёт участок настоящей тишины (точка разреза). `silencedetect` не нужен.
4. LLM, проход 1 — **границы тем**: окна 6 мин с перехлёстом 1 мин (из окна берём границы только из его середины), на входе пронумерованные предложения
   с таймкодами, выход — JSON (через GBNF-грамматику llama.cpp) со списком границ и пометками
   «интро/аутро/реклама».
5. Эмбеддинги предложений (Qwen3-Embedding-0.6B, ~22 мс на предложение) → сходство средних векторов окон ±45 с
   вокруг каждого стыка → глубина провала, порог `mean − 0.5·std`, не ближе 20 с (`analysis::topics`, TextTiling).
   На сценариях с разметкой: полнота 0.65–0.75 при точности ~0.5 — это страховка, не самостоятельная нарезка.
6. Слияние (`analysis::cutting::merge_blocks`): граница LLM с границей эмбеддингов ближе 5 с — подтверждённая;
   границы только эмбеддингов режут лишь блоки длиннее 120 с; содержательные блоки короче 20 с склеиваются с соседом
   (сначала через неподтверждённую границу, при равенстве — с более похожим по эмбеддингам), если вместе ≤90 с.
   В проходе 1 схема ограничивает число блоков окна (один на 25 с); упёрлась в лимит — остаток окна с последней
   границы спрашивается заново (до 3 раз). Кандидат на неподтверждённой границе помечается «проверь».
7. LLM, проход 2 — **оценка каждого кандидата**: самодостаточность, оценка 1–10, причина, заголовок, ключевые слова.
8. Доводка: прилипание к паузам с отступом 0.2–0.4 с, проверка длительности (≤60 цель, ≤~120 предел),
   слишком длинные — пометка или попытка ужать (повторный запрос с просьбой выбрать подотрезок).
9. Результат кэшируется в `~/.cache/shortscutter/analysis/<hash>.cut.json` (ключ — ещё и файл LLM и хэш промптов);
   новый транскрипт удаляет старую нарезку. В приложении это одна задача очереди: распознавание → эмбеддинги → LLM.

Все промпты — в отдельных файлах ресурсов (не в коде): `crates/analysis/prompts/` (вшиты в бинарник),
одноимённые файлы в `~/.config/shortscutter/prompts/` их перекрывают — так промпты правятся без пересборки. LLM — Qwen3.5-9B Q4_K_XL без рассуждений, `-c 12288`, ~5.7 ГБ VRAM;
номера предложений из ответа проверяются кодом (схема гарантирует формат, но не смысл).

## 5. Превью

- mpv декодирует исходник (VAAPI), рендерит кадр в свою FBO-текстуру (размер кадра, мипмапы); текстура
  регистрируется в egui (`register_native_glow_texture`). Подтверждено на 0.5: 60 к/с на 1080p и 4K, GPU ~1–3 мс на кадр.
- **С mpv — только асинхронно**: состояние плеера из `mpv_observe_property`, команды через `mpv_command_async` /
  `mpv_set_property_async`; синхронные вызовы из GL-потока дают взаимное ожидание с таймаутом ~200 мс.
  `MPV_RENDER_PARAM_BLOCK_FOR_TARGET_TIME = 0`, `report_swap` после каждого кадра UI, `MPV_RENDER_PARAM_WL_DISPLAY` — окна.
  Опции: `vo=libmpv hwdec=vaapi hr-seek=yes keep-open=yes config=no load-scripts=no osc=no input-default-bindings=no`.
- Точный seek — `absolute+exact` (в пределах кадра, 90 мс на 1080p); при перетаскивании таймлайна — `absolute+keyframes`.
  Отрезок `[in, out]` — `ab-loop-a/b`, петля бесшовная (граница `out` исключающая).
- Композитор собирает весь холст в свою текстуру размером с превью на экране (egui показывает её как картинку): фон (та же текстура + двухпроходный gaussian blur + затемнение; blur в ¼ разрешения холста
  через мипмап — 0.4 мс, на полном холсте — 7 мс), кропы основного видео
  (скругление — SDF во фрагментном шейдере; рамка, тень и остальные растровые слои — текстуры из `raster`, те же, что у рендера),
  субтитры (растеризуются по текущему времени), баннер.
- Воспроизведение шортса: mpv играет `[in, out]`; при наличии вставки — переключение на второй экземпляр mpv
  с клипом и обратно.
- Растры шаблона для превью считает фоновый поток (последний шаблон); пока растр слоя не готов, композитор растягивает
  прошлый растр этого слоя на новый прямоугольник — перетаскивание мышью не ждёт растеризации.
- Оверлеи редактора (рамка выделения, ручки, линии привязки, сетка, зоны интерфейса Shorts, рамка кадра исходника при кропе)
  рисует egui поверх холста — в рендер не попадают.
- Для исходников > 1080p — опциональный фоновый прокси (720p, H.264 VAAPI, GOP ~0.25 с): seek 4K 330 → 36 мс; создание ~1/6 длительности ролика.

## 6. Рендер

Шортс = конкатенация сегментов: `[обложка] → [основное in..at] → [вставка] → [основное at..out]`.
Каждый сегмент проходит один и тот же граф шаблона (вставка — в режиме «весь экран» или «в слот видео»).

Граф `filter_complex` для сегмента:
- `split` исходника → ветка фона (уменьшить до ¼ → `gblur` → затемнение → увеличить) и ветки кропов основного видео;
- скругление — заранее растеризованная маска-PNG + `alphamerge` (проверено в 0.4, почти бесплатно);
- `overlay` растровых слоёв (PNG из `raster`, тот же растеризатор, что в превью), баннера;
- субтитры — последовательность растров `sc-raster` (одним входом) → `overlay`, таймкоды сдвинуты относительно шортса и вставки;
- `concat` сегментов, аудио — `atrim`/`asetpts` + тишина на обложке.

Кодирование: H.264/HEVC — `*_vaapi` (если доступно) или libx264/libx265; AV1 — libsvtav1; VP9 — libvpx-vp9;
ProRes — prores_ks. Доступность кодировщика определяется при запуске пробным кодированием нескольких кадров
(`-encoders` не достаточно, см. DECISIONS), недоступные — неактивны в UI с подсказкой.
Для VAAPI в хвост графа добавляется `format=nv12,hwupload` (`-vf` вместе с `-filter_complex` нельзя).
Пресет по умолчанию: `h264_vaapi` VBR 12 Мбит/с (maxrate ×1.5, bufsize ×2), AAC 192k; без VAAPI — libx264 veryfast 12 Мбит/с.
Время упирается в граф (CPU), а не в кодировщик: ~26 с на минуту шортса 1080×1920@60 на i5-9400F (замеры — `phases/00-spikes.md`, 0.4).

Очередь: по умолчанию 2 параллельные задачи (настраивается; 3+ почти не ускоряют), прогресс из `-progress pipe:1`,
отмена — завершение процесса и удаление недописанного файла.

## 7. Хранение (XDG)

- `~/.config/shortscutter/` — `settings.toml`, пресеты качества
- `~/.local/share/shortscutter/` — `templates/*.toml`, `library/` (копии ассетов + `library.toml`), `history.toml`, `fonts/`
- `~/.cache/shortscutter/` — `models/` (whisper, LLM, эмбеддинги), `analysis/`, `proxy/`, `tmp/`

## 8. Интерфейс

Вкладки-шаги: **Импорт → Нарезка → Оформление → Экспорт**, плюс **Библиотека** и **Настройки**.

│ Пачка        │     ПРЕВЬЮ 9:16 (живое)       │ Инспектор        │

│ • video2 ⏳  │                               │  Свойства слоя   │

Тёмная тема. Корректная работа в тайлинге Hyprland (диалоги — отдельные окна с понятным `class`/`title`
для floating-правил).
