# Этап 2 — Нарезка по смыслу ⭐

**Цель:** приложение само предлагает шортсы — законченные мысли ≤60 с (до ~120 с при необходимости),
а пользователь быстро проверяет и правит их.

**Читать перед началом:** `docs/ARCHITECTURE.md` §4; `docs/SPEC.md` §2; «Результаты» этапа 0 (модели, скорость, промпты в `spikes/prompts/`).

## Критерии приёмки
- На роликах пользователя большинство предложенных шортсов — законченные мысли (оценивает пользователь).
- Границы не режут слова.
- Часовой ролик анализируется за разумное время (ориентир из этапа 0), интерфейс не зависает.

## Передача дальше

### Шаг 2.1 — Транскрипция (2026-11-13)

**Сделано.**
- `third_party/whisper.cpp` — сабмодуль (shallow), закреплён на d2c6f05 (та же версия, что в спайке 0.2).
  После клонирования: `git submodule update --init`.
- `sc-whisper-sys` — `build.rs` собирает whisper.cpp через `cmake` статически (Vulkan, без OpenMP) + bindgen.
  Первая сборка ~2.5 мин на профиль (dev и release собираются отдельно), дальше из кэша cargo.
- `sc-analysis`: `audio` (ffmpeg → s16 моно 16 кГц в память), `whisper` (безопасная обёртка: VAD, DTW, колбэки прогресса
  и отмены, логи ggml → `log`), `transcript` (слова/сегменты/участки речи, кэш `analysis/<hash>.transcript.json`),
  `models` (large-v3-turbo и Silero VAD: URL Hugging Face, SHA-256, докачка `.part`), `TranscribeJob` — кэш → звук → модель → VAD → речь.
  Пример без GUI: `cargo run --release -p sc-analysis --example transcribe -- <видео> [термин…]` (`SC_CANCEL_AFTER=<с>` — проверка отмены).
- Приложение: после ffprobe ролик сразу встаёт в очередь анализа (по одному); в «Импорте» — стадия и прогресс, «Стоп»,
  «⟳ распознать заново» (удаляет кэш), повтор после ошибки; без моделей — плашка «Скачать модели (1.6 ГБ) / Указать файл…»,
  после загрузки споткнувшиеся ролики перезапускаются сами. В «Настройках» — модели и словарь терминов (по строке на термин).
  `GGML_VK_DISABLE_HOST_VISIBLE_VIDMEM=1` выставляется первой строкой `main`.
- Транскрипт хранит оба таймкода слова: по токенам (`start/end`) и DTW (`dtw`) — решение пользователя по 0.2 не потребует перераспознавания.

**Замеры** (10 мин Twitch-VOD из 0.2, turbo F16 + VAD + DTW): ~25 с (×23–24 реального), 532 слова, 107 участков речи;
звук 0.6 с, загрузка модели 1–4 с, VAD ~5.5 с, остальное — распознавание. RSS ~290 МБ. Отмена: на извлечении звука — сразу,
на распознавании — до конца текущего окна; **VAD не прерывается** (≈1% длительности записи, ~30 с на час).

**Неочевидное.**
- **ffmpeg `-f f32le` сводит стерео в моно без нормировки** (громче в √2, выбросы за ±1). whisper на таком звуке терял
  всю пунктуацию и работал в 1.7 раза медленнее (44 с против 26). Берём `s16le` и делим на 32768 — как whisper-cli.
- **`carry_initial_prompt` хуже обычного prompt.** Со словарём в каждом окне whisper терял реальные фразы, точки в конце сегментов
  и растягивал сегменты до 15–20 с. Оставлен обычный initial prompt: whisper и так тянет скользящий контекст (`no_context`
  чистит его только в начале вызова), словарь работает («КСГО», «Пчевензом» — правильно). Минус: скользящий контекст —
  источник петель («Не трогайте меня…» ×10) и «Спасибо за подписку…» на шуме. Проверить на ролике с голосом; если петли
  мешают — фильтр повторов в 2.2 или `n_max_text_ctx`.
- VAD whisper.cpp всегда на CPU (`whisper_vad_default_context_params`: 4 потока, `use_gpu=false`), из `whisper_full` не настраивается.
  Конец VAD ловим по первому `encoder_begin_callback` — так UI переключает стадию «Поиск речи» → «Речь N%».
- `whisper_full_get_vad_segment_t0/t1` — сантисекунды исходной шкалы, как и таймкоды токенов.
- Текст слова собирается из байтов токенов: токен может разрезать русскую букву UTF-8 пополам.
- HF отдаёт SHA-256 файла в `x-linked-etag` — им и проверяем загрузку. С ПК Hugging Face открывается без VPN.
- Статическая сборка ggml: порядок `whisper, ggml, ggml-vulkan, ggml-cpu, ggml-base` + `vulkan`, `stdc++`.
  `GGML_NATIVE` по умолчанию включён (сборка под этот CPU) — для пакета (этап 8) выключить или собрать варианты.
- Если позже llama.cpp тоже линковать статически — будет конфликт двух копий ggml; проще llama-server отдельным процессом (решить в 2.3).

**Не проверено (нужен пользователь / ручной клик):** загрузка 1.6 ГБ через кнопку (функция проверена тестом на VAD
с докачкой: `cargo test -p sc-analysis -- --ignored`), «Стоп» и «⟳» мышью, удаление ролика во время анализа.


### Шаг 2.2 — Структура текста (2026-11-13)

**Сделано.**
- `third_party/llama.cpp` — сабмодуль (shallow) на теге b11384 (0faee50), той же версии, что бинарники замеров 0.3.
- `sc-llama`: `build.rs` собирает только цель `llama-server` (cmake, статически, Vulkan, без UI/OpenSSL/тестов) — ~4 мин
  на профиль в первый раз; бинарник зависит лишь от `libvulkan`, `libstdc++`. `Server::start` — свободный порт, ожидание `/health`
  (отмена, таймаут 180 с, последние 20 строк лога в ошибке), `embeddings()` пачками по 64, `Drop` убивает процесс.
  Путь к серверу: `SC_LLAMA_SERVER` → рядом с exe → собранный. В 2.3 сюда же — `/v1/chat/completions` с JSON-схемой.
- `sc-analysis::sentences`: `sentences()` (пунктуация, пауза ≥1.2 с, деление >30 с, пометка `repeat`), `pauses()` (промежуток между
  словами + самый длинный кусок без речи по VAD, `Pause::cut()` — куда резать).
- `sc-analysis::topics`: `topic_boundaries()` (TextTiling: окна ±45 с, `mean − 0.5·std`, `min_gap` 20 с), `embed_sentences()`.
  `QWEN3_EMBED` — спецификация модели (URL, SHA-256, размер) для загрузчика.
- Пример: `cargo run --release -p sc-analysis --example structure -- transcript.json` — предложения с отметками «тема?».
- Тесты: синтетика + `tests/data/twitch-10min.transcript.json` (транскрипт 2.1); `cargo test -p sc-analysis -- --ignored topics` —
  сценарии `script-net.json`/`script-scam.json` (из 0.3, с разметкой разделов) на настоящей модели. 64 теста в workspace.
- Спайк подбора параметров — `spikes/06-embed/tiling.py` (нужен запущенный `llama-server --embedding`).

**Замеры.** Сценарии: net — полнота 0.65 (33 кандидата на 26 разделов), scam — 0.75 (27 на 20), точность ~0.5, допуск ±10 с.
Twitch 10 мин: 109 предложений (12 повторов, в основном «Окей. Окей.»), эмбеддинги + запуск сервера ~5 с (запуск 1.1 с).
Скорость эмбеддингов ~22 мс на предложение при любых `-np`/`-ub`/`-c`/`-fa` — накладные расходы сервера на задачу, не GPU;
час речи (~1500 предложений) ≈ 30–35 с — терпимо рядом с ~150 с whisper. VRAM ~0.9 ГБ.

**Неочевидное.**
- В zsh на ПК `$args` без кавычек не разбивается на слова — скрипты замеров писать на bash.
- `pgrep -f`/`pkill -f` по шаблону из той же команды ssh находит саму оболочку (`zsh -c …`) — убивает свою же сессию.
- Инструкция-префикс Qwen3-Embedding («Instruct: … Query: …») на этой задаче полноту не улучшила (net 0.58–0.73, scam хуже).
- На стриме без структуры (Twitch) границы «тем» — по сути паузы между репликами; на роликах с голосом и сценарием должно быть
  осмысленнее, проверить вместе с 2.3 на ролике пользователя.
- `repeat` ловит и естественные повторы («Окей. Окей.»); петлю whisper отличает длина серии — решать в 2.3, не удалять заранее.

**Не сделано / дальше.** В приложение 2.2 пока не встроено: этапы «Структура» и «Нарезка» в очереди анализа и загрузка
модели эмбеддингов (и LLM ~5.6 ГБ) добавятся одной плашкой в 2.3. Кэш эмбеддингов не нужен — они дешевле LLM-прохода.
