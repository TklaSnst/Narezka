## Критерии приёмки (= MVP)
- Встроенные шаблоны визуально близки к референсам.
- Превью и рендер совпадают по положению элементов, текст — по пикселям.
- Свой шаблон создаётся и сохраняется без правки файлов руками.

## Передача дальше

### Шаг 3.1 (2026-11-13)

Сделано:
- `sc-core::template` — полная модель: фоны `blur | color | gradient | image | video` (у картинки и видео — `darken`),
  слои `main_video` (скругление, `border`, `shadow`), `text`, `image`, `capsule`, `shape` (плашка/градиент, `paint = solid | linear`),
  `banner_slot`. Все длины — в долях **ширины** холста. Проверки диапазонов (`TemplateError::BadValue { layer, field }`).
  Общие формулы: `gradient_t` (угол как в CSS), `rounded_rect_coverage` (SDF скругления — маски рендера, растры, шейдер),
  `main_video_crop_px` (чётные пиксели кропа — одинаково в превью и рендере).
- `sc-raster` — общий растеризатор (пока без tiny-skia/cosmic-text — нужны с текстом в 3.2): фон-градиент и фон-картинка (cover + затемнение),
  тень видео (SDF + 3× box blur ≈ гаусс σ = blur/2), рамка (внутрь, кольцо двух SDF), фигура, картинка (вписать, прозрачность).
  `Art { background, layers: [LayerArt { below, above }] }`; `Bitmap::to_pam()` для ffmpeg.
- `sc-render::graph` — полный граф: фон по типу (цвет/картинка — с темпом вывода, видео — `-stream_loop -1` + cover средствами ffmpeg),
  по слоям: растр «под» → видео (маска скругления) → растр «над». Входы описывает `Graph::inputs` (`Mask | Sprite | BackgroundImage | BackgroundVideo`),
  файлы пишет `RenderJob::run`. В `RenderJob` добавлен `src_fps`.
- `sc-compositor` собирает **весь холст** в свою текстуру размером с превью на экране (шейдер `quad.rs`: участок текстуры → прямоугольник,
  SDF-скругление, затемнение, premultiplied); растры `sc-raster` загружаются текстурами с мипмапами при смене шаблона.
  UI показывает одну текстуру (`Player::canvas_texture`, размер — `request_canvas`). Видео-фон — второй экземпляр mpv
  (по кругу, без звука, пауза вместе с основным).
- Для разработки: `SC_TEMPLATE=<файл.toml>` подменяет шаблон пачки (и в приложении, и в `examples/render_short`).
  Тестовые шаблоны — `tools/templates/`.
- Проверено: 93 теста (в т.ч. рендер полного шаблона на настоящем ffmpeg), clippy чистый. В headless sway пять шаблонов
  (размытие + градиент-затемнение + рамка; два экрана со скруглением, тенью и рамкой; фон-картинка + картинка + градиентная плашка;
  фон-видео; фон-градиент) — превью и первый кадр рендера совпадают по положению, кропу и затемнению (на пикселях фона: 176–178 из 255 при darken 0.3).

Неочевидное:
- **Баг этапа 1 исправлен:** при фоне «цвет» рендер выходил в 25 к/с — темп графа задаёт база `overlay`, а `color` по умолчанию 25 к/с.
  Теперь у сгенерированных фонов `r=` / `-framerate` = частота вывода или исходника.
- С базой-генератором (картинка/видео-фон) кадров бывает на 1 меньше (179 из 180 на 3 с) — `shortest=1` обрезает последний кадр. Не критично; вернуться на этапе 7 (склейка сегментов).
- Строка 0 любой текстуры превью — верх кадра (mpv рисует в FBO без переворота), поэтому холст рисуется без переворота, а egui показывает его как есть.
- Растры пересчитываются целиком при любом изменении шаблона (синхронно в UI-потоке). Для перетаскивания мышью в 3.3 нужен кэш по слоям
  (тень 1080 px — десятки мс в debug).
- `rustfmt` на ПК не установлен — код не форматировался автоматически.
