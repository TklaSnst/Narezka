# Этап 9 — Нарезка моментов со стримов

**Цель:** из длинного стрима (Twitch, а также YouTube и Kick, обычно на английском) получить список кандидатов,
то есть интересных и смешных моментов. Пользователь выбирает из них нужные, а приложение собирает живые шортсы:
компоновка меняется по ходу ролика, есть монтаж из нескольких кусков и субтитры на языке речи.

**Когда:** после этапа 8, когда основной проект готов (решение пользователя от 2026-11-15).

**Читать перед началом:** `docs/SPEC.md` §9; `docs/references/streams/README.md`; `docs/ARCHITECTURE.md` §3 (модель Short)
и пайплайн анализа; старый проект `~/work/twitch` (`clips.py`, `chat_overlay.py`, `webcam_detect.py`, `condense.py`,
`film_select.py`). Из него берём **приёмы**, а не код. Сам он делает скучные ролики (оценка пользователя), потому что режет по
категориям и громкости без понимания момента.

## Ответы пользователя (2026-11-15)

- **Источник:** ссылка на VOD или канал из заранее заданного списка. Приложение показывает последние стримы канала,
  а стрим (или сразу несколько) выбирает пользователь либо приложение. Локальный файл тоже остаётся.
- **Длина стримов:** разная. Реально бывает до 10–11 часов (у xQc последние VOD — 9.5–11 ч).
- **Сигналы чата и клипов:** да, при работе по ссылке.
- **Формат:** один кусок или монтаж нескольких, по ситуации. Главное, чтобы было интересно.
- **Компоновка:** настраивается в приложении, есть пресеты.
- **Субтитры:** на языке речи.
- **Мат:** ничего не делаем.
- **Выход:** кандидаты, а выбирает пользователь.
- **Twitch clipper:** делает очень скучные видео, его подход не повторяем.

## Открытые вопросы к пользователю

- [ ] Один реальный стрим и 5–10 таймкодов моментов, которые пользователь нарезал бы сам. Это эталон для оценки поиска (9.0, 9.2).
- [ ] Стартовый список каналов.
- [ ] Кроп «на говорящего» для подкастов и нескольких камер (референс `Uf_oCH_6u9c`). В SPEC §7 авто-слежение за лицом
      было отклонено для своих роликов. Нужно ли оно для стримов?
- [ ] YouTube-стримы: yt-dlp требует вход («not a bot»). Можно ли брать cookies из браузера (`--cookies-from-browser`)?

## Шаг 9.0 — Спайк: источники и сигналы
- [ ] yt-dlp как системная зависимость (проверка при запуске, как у ffmpeg). Twitch-канал → список VOD уже работает
      (`--flat-playlist`, проверено 2026-11-15). Нужно проверить, что yt-dlp на ПК устарел (2026.03) и для YouTube нужен JS-рантайм (deno).
- [ ] Скачать **только звук** 10-часового VOD: время и размер. Анализ идёт по звуку, видео качается только для выбранных моментов
      (`--download-sections` с запасом).
- [ ] Превью без скачивания: mpv играет HLS Twitch напрямую (через ytdl-hook или прямой m3u8). Проверить перемотку по 10-часовому VOD.
- [ ] Чат VOD через Twitch GQL (смещение + текст + эмоуты): работает ли без integrity-токена, сколько занимает на 10 ч.
- [ ] Клипы зрителей по VOD (GQL, `videoOffsetSeconds`) — самый точный сигнал. Посмотреть, как это сделано в `~/work/twitch/twitch_clipper/clips.py`.
- [ ] Звук: перепады громкости, смех и крики. Лёгкий классификатор звуковых событий (YAMNet-подобный, ONNX или ggml) или эвристика.
- [ ] На эталонном стриме пользователя: какой сигнал сколько эталонных моментов ловит. Итог — в «Передаче дальше» и `DECISIONS.md`.

## Шаг 9.1 — Источники
- [ ] Экран «Стримы» (или режим «Импорта»): поле ссылки и список каналов из настроек. У канала — последние VOD
      (обложка, название, дата, длина), выбор одного или нескольких, кнопка «выбрать за меня» (самые длинные или свежие, по настройке).
- [ ] Загрузка: звук целиком, чат, клипы → кэш по id VOD. Видео — только куски принятых кандидатов (с запасом под правку границ).
      Прогресс и отмена — в общей очереди.
- [ ] `Source` с типом «удалённый VOD» (url, платформа, канал, длина, локальные куски). Превью по сети или по скачанным кускам.

## Шаг 9.2 — Поиск моментов
- [ ] Тепловая карта стрима: чат (частота сообщений и «смешные» эмоуты: KEKW, LUL, OMEGALUL, `Clip it`, «?»), клипы, звук.
      Показать её полосой на таймлайне.
- [ ] Окна вокруг пиков → whisper только по окнам (язык определяется автоматически) → LLM по тексту окна с контекстом до и после:
      есть ли момент, где завязка и где развязка, тип (смешное / фейл / злость / победа / неожиданное), заголовок-хук
      на языке речи, причина для пользователя по-русски. Промпты — отдельные ресурсы для режима «стрим».
- [ ] Границы прилипают к паузам и склейкам (как в `cutting`). Кандидаты с оценкой идут в «Нарезку», сортировка по оценке.
- [ ] Метрика на эталоне: сколько моментов пользователя попало в топ-30 кандидатов.

## Шаг 9.3 — Монтаж
- [ ] Модель: у `Short` вместо одного `start..end` — список кусков (возможно, из разных мест источника) со скоростью у каждого.
      Старые пачки читаются как один кусок.
- [ ] «Нарезка»: добавить кусок, повтор момента («ещё раз»), вырезать пустое (по паузам и тишине), ускорить кусок.
- [ ] Рендер — склейка кусков. Субтитры и таймкоды пересчитываются на время шортса.
- [ ] LLM может предложить монтаж: реакция → откат к причине.

## Шаг 9.4 — Сцены компоновки
- [ ] Пресеты-шаблоны: «Сплит игра/вебка», «Сплит вебка/экран», «Игра на весь», «Вебка на весь», «Кадр на чёрном + подпись»,
      «Реакция (две зоны по очереди)».
- [ ] Автопоиск прямоугольника вебки (идея `webcam_detect.py`: статичная контрастная область) → кроп слоя «вебка».
- [ ] Сцены внутри шортса: на таймлайне шортса — смена пресета или кропа с переходом (резко или быстрым наездом).
      Панч-зум на реакцию. Превью и рендер — по общим формулам.
- [ ] Предложение сцен по сигналам (пик реакции → вебка крупно), пользователь правит.

## Шаг 9.5 — Тексты и акценты
- [ ] Хук-заголовок от LLM в слое заголовка, ремарки действий («\*swallows it down\*») как временные текстовые слои.
- [ ] Эмодзи в тексте и субтитрах: цветной шрифт (Noto Color Emoji) в `sc-raster`. Риск: поддержка COLR/CBDT в cosmic-text и tiny-skia.
- [ ] Простые аннотации: круг и стрелка как временные фигуры.
- [ ] (Низкий приоритет) вспышка цветом и тряска на акцентах.

## Критерии приёмки
- По ссылке на 10-часовой Twitch VOD кандидаты готовы за разумное время (цель — меньше 20 мин), видео целиком не качается.
- На эталонном стриме пользователя бо́льшая часть его моментов есть среди кандидатов.
- Шортс со сменой сцен, монтажом из двух кусков и субтитрами на английском: превью совпадает с рендером.
- Пользователь оценивает: это интересно, а не скучно, как у Twitch clipper.
